PlantCare AI System Architecture & Methodology

A unified investigation into the convergence of Wireless & Mobile Computing (WMC), Deep Learning Computer Vision, and Cloud Computing infrastructure for agricultural disease diagnosis.

Primary Objective

Objective & Problem Statement

Foliar plant diseases account for up to 30-40% of agricultural yield loss in tomato crops globally. Early human diagnosis by agricultural extension workers is slow, labor-intensive, and inaccessible to smallholder farmers.

PlantCare AI addresses this gap by engineering an end-to-end, lightweight automated diagnostic web system. The application performs instant leaf pathogen classification, generates confidence estimates, and provides actionable agronomic intervention plans via accessible web and mobile touchpoints.

1. Web & Mobile Computing (WMC)

In rural and agricultural field operations, connectivity is often intermittent and device hardware is constrained.

Key Implementations:
  • Responsive Viewports: Adaptive CSS flex/grid layout matching mobile devices, tablets, and desktop workstations.
  • Client-Side Image Compression: Reduces network payload by previewing and verifying images prior to transmission.
  • Low Latency REST API: JSON-based payloads for quick client-server roundtrips even over 3G/4G networks.
2. Machine Learning

Utilizes deep Convolutional Neural Networks (CNNs) optimized for image classification through Transfer Learning.

Key Implementations:
  • MobileNetV2 Architecture: Employs inverted residual blocks and depthwise separable convolutions for high efficiency.
  • Preprocessing Pipeline: Standardizes input RGB tensors to 224×224 resolution with zero-centered [-1, 1] normalization.
  • Softmax Multi-Class Output: Produces normalized probability distributions across 5 distinct tomato foliar classes.
3. Cloud Computing

Cloud deployment ensures ubiquitous access, decoupled persistent storage, and horizontal auto-scaling without dedicated on-premise hardware.

Key Implementations:
  • Stateless Container / PaaS Deployment: Ready for hosting on Google Cloud Run, Render, or Heroku via standard Procfile.
  • Decoupled Object Storage: Architecture supports Firebase Cloud Storage and AWS S3 for leaf image archival.
  • Cloud DB Integration: SQLite for immediate local zero-config runs, with documented switch to Google Firebase Firestore.
